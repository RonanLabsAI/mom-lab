## Review Focus

1. Schema stricter than the gold: a schema that rejects any gold reference caps accuracy below 100 and biases the gate against constrained decoding. Every one of the 1,000 test and 300 dev gold references must validate (Task 1 test).
2. Router mutates the request: LiteLLM silently dropping `response_format`, `chat_template_kwargs`, `top_k` or `seed` would make the arm something other than what the card says. The parity control (8B zero-shot unconstrained, byte-identical to the stored Part D-C outputs) and a payload test catch it (Tasks 2 and 4).
3. Constrained greedy loops: grammar-constrained greedy decoding can emit whitespace until `max_tokens`. Truncations count as wrong (harness rule) and are reported per arm; the smoke gate fixes the token limit before the test run (Task 2 smoke check).
4. Proprietary or PHI content in a release or eval set (master plan Review Focus 5): the release checker refuses FlyCurrent/RetenzAI paths and PHI patterns, and MedCalc notes are public de-identified PMC case reports, which the plan documents (Task 5 test).
5. Wrong comparator in the paper: the 11.6x token claim compares the adapter with a thinking trace. Once the gate runs, the paper must also state the token ratio against the constrained arm, and if it has not run, the claim is labelled as pending (Task 6 check).
